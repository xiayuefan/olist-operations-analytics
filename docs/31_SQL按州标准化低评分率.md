# 第 39 课 SQL 按州标准化低评分率

直接汇总时，延迟组和按时或提前组各自有一套客户州分布。要比较两组在相同州构成下的低评分率，可以给两组的州内低评分率乘上同一套权重，再分别加总。这个方法叫直接标准化。[CDC 直接标准化公式](https://www.cdc.gov/nchs/hus/sources-definitions/age-adjustment.htm)

## Q22 比较直接汇总和按州标准化的结果

沿用 Q20 的下单时间、延迟资格和最新有效评分规则。两种算法都使用延迟组和按时或提前组均有有效评分订单的州。`excluded_rated_orders` 显示因缺少其中一组而未纳入的有评分订单数。

| `comparison_method` | 如何计算每组整体低评分率 |
| --- | --- |
| `observed` | 该组所有纳入州的低评分订单数 ÷ 该组所有纳入州的有效评分订单数 |
| `state_standardized` | 把各州该组的低评分率乘以共同权重后相加。共同权重取该州两组有效评分订单数之和，占全部纳入订单的比例。 |

例如，某州占合并样本的 40%，它在两组的标准化计算里都占 40%。`low_score_gap_pp` 用未舍入的延迟组低评分率减去按时或提前组低评分率，单位为百分点。标准化后的差值描述在同一州构成下的关联，州内的品类、卖家和月份差异仍可能影响结果。

查询已在独立 MySQL 8.0.37 中运行，两行结果与 Python 重算一致。当前数据的 27 个州均满足条件，两行都纳入 **95,560 笔**有有效评分的订单。
