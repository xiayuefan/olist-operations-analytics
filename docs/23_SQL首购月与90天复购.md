## Q13 按首购月计算 90 天复购率

1. 继续用 2017-01 至 2018-08 下单且最终已交付的订单。`customer_id` 用来连接订单与客户表，`customer_unique_id` 用来识别同一客户。窗口内第一单的下单月份就是该客户的 `first_purchase_month`。
2. `ROW_NUMBER()` 给客户的订单编号，`LEAD()` 取下一单的下单时间。保留编号为 1 的行，就得到每位客户的第一单和第二单。只要第二单在首购后 90 天内（含第 90 天同一时刻），该客户计为复购一次。同一时刻提交的两笔不同订单按订单 ID 排序，仍按两笔订单处理。
3. 观察范围截至 **2018-09-01 00:00:00 之前**。只有首购时间加 90 天早于这个边界，才有资格完整观察。月内只要有客户尚未观察满 90 天，就保留该月的客户人数，把整组复购人数和复购率留为 `NULL`，让展示出来的各组使用相同的观察长度。

| 字段 | 含义 |
| --- | --- |
| `cohort_customers` | 该首购月的客户数 |
| `eligible_customers` | 其中已获得完整 90 天观察期的客户数 |
| `pending_customers` | 其中尚未获得完整 90 天观察期的客户数 |
| `repeat_90d_customers` | 整组可比较时，90 天内至少再买一笔的客户数 |
| `repeat_90d_pct` | 整组可比较时，90 天复购客户数 ÷ 该组客户数 |

已在独立 MySQL 8.0.37 中执行，并与直接读取 Parquet 得到的 Pandas 结果逐行核对。查询返回 20 个首购月，`cohort_customers` 合计与 Q11 的 **93,104 位客户**一致。逐月可用 `eligible_customers + pending_customers` 核对 `cohort_customers`。

## 我的理解

1. 最后一个可以完整比较的首购月是哪个月？这个月的 90 天复购人数、分母和复购率各是多少？
2. 第一个复购率为 `NULL` 的月份里，`pending_customers` 是多少？如果把这月的 `NULL` 当成 0%，会误解成什么？
