# 第 30 课 SQL 客户购买频次与月度结构

上一课按客户所在州看成交额。这一课切换到客户粒度，先看每位客户买过几次，再按月区分首次购买订单和后续购买订单。

沿用 2017-01 至 2018-08 的下单窗口，只纳入最终已交付的订单。本文的「首次」指这段窗口内观察到的第一笔已交付订单。窗口开始前的购买不参与编号。

## Q11 每位客户买过几次

先用 `customer_id` 连接订单与客户记录，再用 `customer_unique_id` 分组。第一层 `COUNT(*)` 计算每位客户的订单数，第二层 `COUNT(*)` 计算每个频次组有多少位客户。`4+` 包含购买 4 次及以上的客户，`delivered_orders` 仍然累加实际订单数。

如果某位客户买了 3 次，`3` 这一组的 `customer_count` 加 1，`delivered_orders` 加 3。用 `delivered_orders` 求和，应核对到 **96,211 笔**。要数买过至少两次的客户，加总 `2`、`3`、`4+` 三组的 `customer_count`。

## Q12 每月的订单有多少来自后续购买

`ROW_NUMBER()` 按 `customer_unique_id` 给每位客户的订单从早到晚编号。`purchase_rank = 1` 是窗口内首次购买，`purchase_rank > 1` 是后续购买。先在整个窗口内编号，再按下单月份汇总，因此同一客户跨月购买时不会重新从 1 开始。

| 字段 | 含义 |
| --- | --- |
| `first_purchase_orders` | 当月属于客户窗口内首次购买的订单数 |
| `later_purchase_orders` | 当月属于客户窗口内后续购买的订单数 |
| `later_order_share_pct` | 当月后续购买订单数 ÷ 当月已交付订单数 |

两种订单数相加等于当月已交付订单数。20 个月的首次购买订单数相加，应等于 Q11 的客户数合计，因为每位客户只会有一笔编号为 1 的订单。

同一位客户当月下了两笔后续订单，会给 `later_purchase_orders` 增加 2。这个指标以订单为分母。后续的固定窗口复购率会以有足够观察时间的客户为分母。

两条查询已在独立 MySQL 8.0.37 运行，并与直接读取 Parquet 得到的 Pandas 结果逐行核对。Q11 有 4 个频次组，Q12 有 20 个月。
