## Q17 核对延迟率的分母

样本仍为 2017-01 至 2018-08 下单且最终已交付的订单，共 **96,211 笔**。沿用订单清洗得到的 `is_valid_delay` 和 `delivery_delay_days`。实际送达日期减预计送达日期得到自然日差。当日送达是 0，提前送达是负数，晚于预计日期才记为延迟。

`COUNT(*)` 数已交付订单。`COUNT(delay_days)` 只数日差非空的订单，也就是可判断延迟的分母。`unassessable_orders` 保留无法判断的数量。比如某笔已交付订单没有实际送达时间，它会计入已交付数，延迟与否仍未知。

## Q18 按延迟程度分档

把可判断的订单分成按时或提前、延迟 1–3 天、4–7 天、8–14 天、15 天及以上五档。`share_of_valid_pct` 的分母包括全部可判断订单。各档的 `order_count` 相加应等于 Q17 的 `valid_delay_orders`。四个延迟档的笔数相加应等于 `late_orders`。

两条查询已在独立 MySQL 8.0.37 中运行。使用 Pandas 从 Parquet 的日期字段重算资格和自然日差后，两张结果表逐行一致。
