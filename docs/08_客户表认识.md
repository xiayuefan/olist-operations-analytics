# 客户表第一步：客户记录、客户身份与订单关联

评价阶段已完成独立复现和粒度核对。本课打开 notebooks/10_客户表清洗.ipynb，先弄清两个客户 ID，再检查客户记录与订单的关联。本次只读取、检查和关联，地区与邮编规范留到下一步。

## 先区分两个 ID

| 字段 | 用途 | 当前表中是否唯一 |
| --- | --- | --- |
| customer_id | 订单关联的客户记录标识；与订单表连接 | 是，99,441 个 |
| customer_unique_id | 跨订单识别同一客户的标识；用于后续客户分组 | 否，96,096 个不同值 |

一行对应一个 customer_id 的客户记录。相同 customer_unique_id 可以出现在多行，对应不同 customer_id。不能把客户记录行数直接当作不同客户数，也不能仅凭字段名含 unique 就认定该列是当前表主键。

字段含义参照原始目录的中文数据字典：

| 字段 | 含义 |
| --- | --- |
| customer_id | 与订单表连接的客户记录 ID |
| customer_unique_id | 跨订单客户标识 |
| customer_zip_code_prefix | 客户邮编前五位，保留为字符串 |
| customer_city | 客户所在城市 |
| customer_state | 客户所在州或联邦区的缩写 |

customer_unique_id 是数据中用于识别客户的标识，不等同于对现实世界自然人的完全识别。地区信息先保留记录原值，后续按指标和时间口径使用。

## 当前数据的检查基线

| 检查项目 | 数量 |
| --- | ---: |
| 客户记录数 | 99,441 |
| customer_id 不同值数 | 99,441 |
| customer_unique_id 不同值数 | 96,096 |
| 两种 ID 缺失或空白字符串 | 均为 0 |
| customer_id 重复行数，首条之后 | 0 |
| customer_unique_id 重复行数，首条之后 | 3,345 |
| 整行重复数，首条之后 | 0 |
| 对应多个 customer_id 的 customer_unique_id 数 | 2,997 |
| 单个 customer_unique_id 最多对应 customer_id 数 | 17 |

3,345 是重复行数，2,997 是对应多条客户记录的客户标识数，两者不能混用。

当前 customer_id 非空且唯一，可作为本表主键。相同 customer_unique_id 的多行不是本次需要直接删除的重复错误；删行可能让部分订单失去 customer_id 匹配，也会丢失对应记录的地区信息。

## 与订单的连接

订单原表提供 customer_id，因此先按它关联客户表，才能把 customer_unique_id、城市和地区信息带入订单。

本次当前文件中，订单侧 customer_id 也非空且唯一，故使用 one_to_one 验证观察到的一对一关系。不要把这个数据快照的关系当作所有电商数据的通用规则。

| 检查项目 | 数量 |
| --- | ---: |
| 订单 customer_id 无法匹配客户表的订单数 | 0 |
| 客户记录没有对应主表订单的数量 | 0 |
| 关联后订单行数 | 99,441 |
| 匹配成功订单数 | 99,441 |
| 未匹配客户的订单数 | 0 |

关联时保留全部订单，先检查主键与反向覆盖，再验证连接关系。原始表保留，关联结果另存为内存中的新表。

## 现在还不能把 2,997 直接称为复购客户

本次计数仅说明同一客户标识对应多条客户记录。复购分析还需要：

- 明确哪些状态的订单算有效购买。
- 确定购买事件和分析时间范围。
- 明确至少几次购买算复购，以及不同客户的观察窗口是否可比较。

取消、未交付、边界月份等情况留待后续订单口径与客户分析阶段处理。本课先建立正确关联，不提前把当前计数当作最终复购结论。
