## Q25 核对单卖家订单的覆盖范围

继续使用 2017 年 1 月至 2018 年 8 月下单且最终已交付的 **96,211 笔订单**。先按订单汇总商品明细，用 `COUNT(DISTINCT seller_id)` 数一笔订单涉及多少个不同卖家。若一笔订单有三条商品明细，三条都来自同一卖家，该单的 `seller_count` 就是 1。

单卖家订单数、多卖家订单数和没有商品明细的订单数相加，应等于 `delivered_orders`。

## Q26 汇总单卖家订单的履约和评分

Q26 用 `HAVING COUNT(DISTINCT seller_id) = 1` 筛出单卖家订单，再用 `MIN(seller_id)` 取出这个唯一的 ID。订单关联每单最新有效评分后仍保持一行一单，再按卖家计数。

| 字段 | 含义 |
| --- | --- |
| `single_seller_orders` | 该卖家在窗口内的单卖家已交付订单数 |
| `valid_delay_orders`、`late_orders` | 可判断延迟的订单数、其中延迟的订单数 |
| `late_rate_pct` | `late_orders` ÷ `valid_delay_orders` × 100 |
| `rated_orders`、`low_score_orders` | 有最新有效评分的订单数、其中最新评分为 1 或 2 星的订单数 |
| `low_score_rate_pct` | `low_score_orders` ÷ `rated_orders` × 100 |

延迟与评分的资格各自判断。例如，一笔订单缺评分但有可靠的实际与预计送达日期，仍参与延迟率计算。分母为 0 时，相应的比率保留 `NULL`。

SQL 展示单卖家订单量最高的 10 位卖家。读表时可同时看比率和对应的订单数。例如，两个卖家的低评分率都为 10%，分母分别是 10 和 1,000 时，对应的是 1 笔和 100 笔低评分订单。延迟率和低评分率反映与该卖家相关的订单表现，承运、地区和商品等因素也可能影响结果。

两条查询已在独立 MySQL 8.0.37 中运行。覆盖结果和全部 2,925 位卖家的汇总均与 Pandas 逐行一致。
