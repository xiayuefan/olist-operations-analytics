## Q09 比较各州的规模和客单价

沿用 2017-01 至 2018-08 下单窗口和已交付订单口径。先在 `order_items` 按订单汇总商品金额，再把一行一单的金额和客户州连到订单。最终按 `customer_state` 聚合。

| 字段 | 含义 |
| --- | --- |
| delivered_orders | 该州的已交付订单数 |
| missing_item_orders | 该州已交付订单中缺商品明细的数量 |
| goods_gmv_brl | 该州商品成交额 |
| goods_aov_brl | 该州商品成交额除以有商品明细的已交付订单数 |
| order_share_pct | 该州已交付订单数占全部州的比例 |
| gmv_share_pct | 该州商品成交额占全部州的比例 |

本批窗口的已交付订单都有商品明细，可以比较两种份额。如果某州的成交额份额小于订单份额，它的商品客单价就低于整体。各州订单数相加应为 **96,211 笔**，成交额合计应为 **13,181,027.13 BRL**。

## Q10 定位 11 月增量的需求地区

按客户所在州计算 10 月和 11 月的已交付商品金额。`change_brl` 为 11 月减 10 月，`net_change_share_pct` 用该州变化除以全平台净变化。州层和品类层分别对同一笔全平台变化做分组，两组各自加总都应得到 **339,517.72 BRL**。

两条查询都在独立 MySQL 8.0.37 运行，并与 Pandas 逐行核对，各返回 27 行。

请发来两张表各自的第一行。用第一张表的订单份额与成交额份额判断该州的商品客单价和整体相比处于哪一侧，再用第二张表说明哪个州贡献了最多净增量。
