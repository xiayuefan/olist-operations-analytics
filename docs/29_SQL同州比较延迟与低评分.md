## Q20 在同一个州内比较两类订单

沿用 Q19 的订单范围、最新有效评分和 1–2 星低评分口径。用 `customer_id` 连接客户表，取 `customer_state`。延迟天数大于 0 归入延迟组，等于或小于 0 归入按时或提前组。

| 字段 | 含义 |
| --- | --- |
| `on_time_rated_orders`、`late_rated_orders` | 两组各自有有效评分的订单数，也是各自低评分率的分母 |
| `on_time_low_score_orders`、`late_low_score_orders` | 两组各自收到低评分的订单数 |
| `on_time_low_score_pct`、`late_low_score_pct` | 两组各自的低评分率，单位为百分比 |
| `low_score_gap_pp` | 延迟组低评分率减按时或提前组低评分率，单位为百分点 |

`NULLIF` 让分母为 0 的比率留空。差值先用保留多位小数的比率计算，再四舍五入为两位小数。用表上两个已舍入的比率相减，末位可能差 0.01 个百分点。

结果按有有效评分的订单总数排序。读差值时同时看两个分母。例如一组只有 5 笔有评分订单，其中 1 笔的评分变化就可能让低评分率变动 20 个百分点。查询在独立 MySQL 8.0.37 中返回 27 行，与 Pandas 逐行一致。两列有评分订单数合计 **95,560 笔**，与 Q19 一致。

## 我的理解

1. 第一行是哪个州？这个州两组的低评分率分别是多少，差多少个百分点？
2. 找一个 `late_rated_orders` 不超过 10 且至少有一笔低评分的州。这个州有多少笔延迟且有评分的订单？如果其中一笔从低评分变为非低评分，延迟组的低评分率会下降多少个百分点？
