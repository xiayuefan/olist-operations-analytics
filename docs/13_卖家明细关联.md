# 卖家第二步：明细关联与控制总额

第十四份 Notebook 的四题核心理解正确。字段名统一为 seller_id。第三题补充：左侧多条商品明细可属于同一卖家，右侧卖家属性表的 seller_id 唯一，因此使用 many_to_one。这里检查的是明细与卖家记录的关系。

第四题中，“找不到卖家表的明细行数为 0”表示每条商品明细的卖家 ID 都能找到属性记录，并不能证明邮编、城市和州的地理对应全部正确。

本课打开 notebooks/15_卖家明细关联.ipynb。五个代码单元可从原始 CSV 独立运行，不依赖第十四份 Notebook 的内存变量。

## 关联前后的粒度

| 表 | 一行代表什么 | 主键 |
| --- | --- | --- |
| sellers_clean | 一个卖家的属性记录 | seller_id |
| items_clean | 一笔订单中的一条商品明细 | order_id + order_item_id |
| items_with_sellers | 一条商品明细，补入卖家属性 | order_id + order_item_id |

本课增加属性，没有按卖家聚合。一个卖家在输出表中出现多次是正常的，不能按 seller_id 删除销售明细。

## 操作顺序

1. 原始卖家和商品明细按字符串读取，邮编保留前导零。
2. 卖家副本规范地区格式，保留地区核查标记；复用 clean_order_items 规范明细主键和整数分。
3. 检查明细卖家 ID 覆盖，以销售明细为左表，按 seller_id 做多对一左连接。
4. 检查匹配状态、组合主键、明细行数、商品金额与运费。
5. 看一个卖家对应的多条真实销售明细，比较明细行数与不同订单数。

validate 检查右侧卖家 ID 唯一，不替你去重。sellers_match 为 both 只表示找到卖家记录。

## 本次预检查结果

| 检查项目 | 关联前 | 关联后 | 差额 |
| --- | ---: | ---: | ---: |
| 商品明细行数 | 112,650 | 112,650 | 0 |
| 商品金额（分） | 1,359,164,370 | 1,359,164,370 | 0 |
| 运费（分） | 225,190,954 | 225,190,954 | 0 |

关联后组合主键重复数为 0，全部 112,650 条明细匹配卖家。涉及 98,666 个不同订单、3,095 个不同卖家。这些是全量商品明细的覆盖，没有筛选订单状态或日期。

控制总额必须与同来源明细一致。如果数量或金额改变，应先查右侧重复键、连接方式、过滤条件、金额缺失等原因，不直接改金额凑平。

样本卖家有 2,033 条明细、涉及 1,854 个不同订单。明细数不等于订单数，原因留给理解题解释；后续按卖家聚合时要选对 size 与 nunique。
