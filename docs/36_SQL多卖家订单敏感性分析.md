## Q28 比较两种订单口径

继续使用 2017 年 1 月至 2018 年 8 月下单且最终已交付的订单。先按 `order_id + seller_id` 去重，再数一笔订单涉及几个卖家。每笔订单在同一卖家的指标里最多计一次。比如一笔订单涉及 A 和 B，各自的 `all_related` 订单数都加 1，全平台仍只有一笔订单。

| `order_scope` | 纳入范围 |
| --- | --- |
| `single_seller_only` | 订单里只有该卖家，沿用 Q26 口径 |
| `all_related` | 订单里出现该卖家，包括涉及其他卖家的订单 |

选全部关联订单数最多的五位卖家，每位卖家展示两行。两行的 `related_orders` 相减，就能数出纳入了多少笔涉及该卖家的多卖家订单。延迟率和低评分率各用自己的有效订单数作分母。分母为零时，比率保留 `NULL`。

`all_related` 使用整笔订单的送达结果和最新有效评分。同一笔多卖家订单的结果会进入多位卖家的汇总。两种口径的差值用于判断卖家指标对纳入范围有多敏感，具体原因仍需检查订单明细和配送记录。

已在独立 MySQL 8.0.37 中运行。五位卖家的十行结果与 Pandas 重算一致。

## 我的理解

1. 看第一位卖家的两行。纳入多卖家订单后增加了多少笔关联订单？延迟率和低评分率分别升了还是降了？用表上显示的数字算出变化的百分点。
2. 一笔低评分订单同时涉及 A、B 两位卖家，在两种口径下各会给他们增加多少笔低评分订单？为什么不能把各卖家的 `all_related` 订单数直接相加，当作全平台订单数？
