# 评价表第一步：粒度、候选主键与一单多评

支付阶段的函数输入、返回值及两类金额核对已经讲解并补齐理解。本课进入评价表，为后续订单差评率、延迟与差评关联分析准备数据。

## 本次目标

打开 notebooks/08_评价表清洗.ipynb。本次先读取和检查原始字符串，不删除记录，不确定一单多评的最终取值规则。

一行是与一个订单关联的评价记录。先确认 review_id、order_id 的唯一性，再检查二者组合。字段名字带 ID 不等于它在当前文件里一定能作为单列主键。

## 字段含义

以下说明参照原始目录中的中文数据字典 数据含义.csv；原始值以实际数据为准。

| 字段 | 本课使用的含义 |
| --- | --- |
| review_id | 评价标识，需要检查其唯一性和关联关系 |
| order_id | 该记录对应的订单 ID |
| review_score | 客户体验评分，数据字典定义为 1～5 分 |
| review_comment_title | 客户填写的评论标题 |
| review_comment_message | 客户填写的评论正文 |
| review_creation_date | 评价问卷创建、发送的日期 |
| review_answer_timestamp | 客户提交评价的时间 |

review_answer_timestamp 不是商家或客服回复时间。review_creation_date 也不能直接解释为客户提交评价的时间。两者的类型、时间顺序和异常情况留到后续检查。

没有评论标题或正文，仍可能有有效评分；不能因为没有文字就直接删除整条评价。

## 订单粒度为什么需要额外处理

| 每单评价记录数 | 订单数 |
| --- | ---: |
| 1 | 98,126 |
| 2 | 543 |
| 3 | 4 |

多评订单数为 543 + 4 = 547。额外评价记录数为 543 × 1 + 4 × 2 = 551，因此多评订单数与 order_id 首条之后的重复行数不同。

如果直接把评价明细连接到订单主表，多评订单会出现多行；后续累加商品金额或统计订单时可能重复。进入订单分析前，需要明确如何从多条评价形成订单级结果。

可以比较最终一次有效评分、首次有效评分、任一低分等规则的含义；具体使用哪种规则，需要先检查评分、时间和多评样本，并明确分析问题。本课不直接选第一条或最后一条，也不把多条评价简单当作相互独立的订单。
