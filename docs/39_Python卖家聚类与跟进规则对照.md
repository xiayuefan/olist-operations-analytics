Q29 按订单量、延迟率和低评分率把卖家分成三个簇。Q27 按两项比率是否高于平台基线筛选跟进对象。本课把这两个结果放在同一张表里，看各簇有多少卖家满足规则。


## Q31 按簇统计规则入选情况

沿用 Q29 的 **K=3、种子 42** 和 Q27 的筛选规则。每位参与聚类的卖家都有至少 50 笔可判断延迟订单和至少 50 笔有评分订单。两项平台基线仍用全部单卖家订单计算。卖家延迟率和低评分率都严格高于对应基线时，记为规则入选。

| 字段 | 含义 |
| --- | --- |
| `sellers` | 该簇卖家总数 |
| `rule_candidates` | 该簇符合 Q27 规则的卖家数 |
| `rule_candidate_share_pct` | `rule_candidates` ÷ 该簇 `sellers` × 100 |

每位卖家只属于一个簇，所以三个簇的 `rule_candidates` 相加可与 Q27 的入选总人数核对。聚类根据三个特征到簇中心的距离分组。规则逐位比较两个比率。即便一个簇的整体延迟率和低评分率同时偏高，其中的卖家也可能只满足一项阈值。

已核对 Python 的入选卖家 ID 与 Q27 的 MySQL 全量名单一致。三个簇的卖家数合计为 408 位。

## 我的理解

1. 各簇分别有多少位卖家符合规则？哪个簇的入选比例最高？用该簇的入选人数和总人数验证这个比例。
2. 如果把入选比例最高的簇作为跟进清单，会额外纳入多少位未满足规则的卖家？会漏掉其他簇的多少位规则入选卖家？
