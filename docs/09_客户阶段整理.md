## 函数如何串起来

公共函数位于 src/customers_cleaning.py，关键位置有目的和粒度注释。

| 函数 | 输入 | 返回及粒度 |
| --- | --- | --- |
| clean_customers | 原始客户字符串表 | 客户工作副本，一行一个 customer_id |
| check_customer_locations | 原表、工作表 | 缺失、空白、规范变化检查表 |
| customer_field_changes | 原表、工作表 | 真正变化的字段清单；本数据为空 |
| join_orders_customers | 订单原表、客户工作表 | 一行一个订单 |
| summarize_city_orders | 订单客户关联表 | 一行一个州+城市组合 |
| summarize_customer_identity | 客户工作表 | 一行一个 customer_unique_id 的映射观察 |
| reconcile_customer_totals | 订单原表、工作表、关联表、地区表 | 数量控制表 |

```python
# 原始客户记录始终保留，下面返回新的工作表。
customers_clean = clean_customers(raw_customers)

# 按 customer_id 连接，而不是按 customer_unique_id。
orders_with_customers = join_orders_customers(raw_orders, customers_clean)

# 同名城市按州区分，输入表已经是一行一个订单。
city_orders = summarize_city_orders(orders_with_customers)

# 客户标识观察表不是订单连接的替代客户维表，也不是复购标签。
identities = summarize_customer_identity(customers_clean)

controls = reconcile_customer_totals(
    raw_orders, customers_clean, orders_with_customers, city_orders
)
```

当前原始数据中两侧 customer_id 均唯一，本阶段延续课堂 one_to_one 检查。客户维表里暂时没有订单使用的记录可以保留，控制总额只比较本批订单实际匹配的客户标识。

## 地区规则补充

1. 邮编按字符串保留，只去首尾空白。五位数字格式不符就标记，不自动补零、截断或猜测。
2. 城市去首尾空白并统一小写；保留词语中间的空格，不进行模糊合并。
3. 州去首尾空白并统一大写；分别检查两位字母格式与参考表成员关系。
4. 地区问题保留标记和原始来源，不删除客户或订单记录。

州代码采用 [IBGE 官方州/联邦区接口](https://servicodados.ibge.gov.br/api/v1/localidades/estados?orderBy=nome) 核对的参考快照，位于 docs/references/ibge_state_codes_v1.json。脚本从本地快照读取，无需联网。它仅验证州代码，不能替代邮编与城市的一致性核查。

例如，AA 是两位大写字母，格式检查通过，但参考代码检查会将它标记为未知。这说明“格式正确”和“值属于允许范围”是不同检查。

## 为什么有两个地区有效性标记

flag_customer_location_needs_review 是邮编、州格式、未知州、城市缺失等标记的并集。

can_group_by_city_state 只依赖州、城市是否可用。邮编异常但州和城市可用的订单，仍可参与州城市订单统计；不能因为一个字段有问题就把整个订单从所有指标删除。

地区统计只在筛选表达式中排除不可分组记录，完整订单表仍保留。被排除订单数量单独报告。本数据的排除数为 0。

## 地区汇总怎么核对

一行一个订单的关联表有 99,441 行。按州和城市聚合后，地区表有 4,310 行，代表不同组合。

```python
city_orders = eligible_orders.groupby(
    ["customer_state", "customer_city"], as_index=False
).agg(
    order_count=("order_id", "size")
)
```

order_count 合计仍为 99,441，数量守恒。控制表同时检查订单行数、不同订单数、匹配数量和客户标识数。地区表行数减少不等于订单被删除。

最新的评价阶段也使用同样的粒度原则：源记录数要通过合适的计数列追溯，不能要求不同粒度的表行数相等。

## 同一客户标识的不同地区值

当前有 250 个 customer_unique_id 对应多个邮编值，122 个对应多个州+城市组合，39 个对应多个州标签。

这些是记录中地区字段存在差异的观察，原因尚未核实，不直接解释为搬家或客户身份变化。保留各 customer_id 的位置，让订单关联到各自的客户记录，不能任意按 customer_unique_id 取一条地址覆盖历史订单。

2,997 仍只表示客户标识对应多条记录。最终复购分析还需明确有效订单状态、购买事件、日期范围和观察窗口。
