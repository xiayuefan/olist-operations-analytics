## 函数如何组织

公共函数位于 `src/items_cleaning.py`。

| 函数 | 输入 | 返回值 |
| --- | --- | --- |
| clean_order_items | 原始商品明细表 | 转换类型、增加金额分及业务标记的新表 |
| check_item_references | 明细表、商品键、卖家键 | 商品与卖家关联检查表 |
| aggregate_order_items | 明细工作表 | 一行一个订单的汇总表 |
| join_orders_items | 订单主表、商品汇总表 | 保留全部订单的关联表 |
| reconcile_item_totals | 明细、汇总、关联后表 | 数量与金额核对表；不一致时停止 |
| summarize_item_metrics | 明细、汇总、关联后表 | 指标字典，计数与金额保留整数 |

它们可以按下面顺序组合：

```python
items_clean = clean_order_items(items_raw)
order_item_summary = aggregate_order_items(items_clean)
orders_with_items = join_orders_items(orders_raw, order_item_summary)
reconcile = reconcile_item_totals(items_clean, order_item_summary, orders_with_items)
metrics = summarize_item_metrics(items_clean, order_item_summary, orders_with_items)
```

商品和卖家关联检查安排在汇总、导出前，任何一项不为零就先停止核查。

## 整理时补充的类型规范

- `order_id`、`product_id`、`seller_id` 保留字符串标识。
- `order_item_id` 规范为正整数；转换后再次检查组合唯一性，避免 `01` 与 `1` 等字符串归一后出现重复。
- 商品金额和运费始终从原始字符串换算为整数分；原金额数值列用于查看。
- `shipping_limit_date` 转为时间类型；缺失仍保留并设标记，非空解析失败则停止核查。
- 关联后汇总列使用可空整数 `Int64`，未匹配订单金额为 `<NA>`。
- 零运费是业务特征，保留；零商品金额另设核查标记。遇到缺失金额、负数或不足一分的精度时停止核查，不擅自填零、取绝对值或舍入。

这次没有删除任何原始订单或明细。保留不同指标各自的有效样本条件；订单表八条时间核查规则与本表覆盖标记分开记录。

## 仍需核查的事项

发货截止时间中存在 2020-04-09 的记录，而这批订单下单时间截至 2018 年。日期能解析不等于业务合理，当前保留原值；后续结合下单时间检查这类记录，再评估是否适合发货时效分析。

订单级实际交物流时间也不能直接当成每个卖家的独立交物流时间，尤其要考虑多卖家订单的归因问题。

当前 GMV 是全量历史已交付订单的商品金额基线，不含运费，不等同于支付额或平台收入；支付对账、正式分析窗口和敏感性分析仍待后续完成。
