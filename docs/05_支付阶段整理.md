## 函数怎样组合

公共函数位于 src/payments_cleaning.py，继续复用上一阶段的精确金额转换和商品清洗、聚合函数。

| 函数 | 输入 | 返回 |
| --- | --- | --- |
| clean_order_payments | 原始支付字符串表 | 带类型转换、整数分和核查标记的新 DataFrame |
| aggregate_order_payments | 支付工作表 | 一行一个订单的支付汇总表 |
| join_orders_payments | 原始订单表、支付汇总 | 保留全部订单字段的支付关联表 |
| reconcile_payment_totals | 支付工作表、汇总、关联表 | 明细、汇总、关联后的数量和金额控制表 |
| reconcile_order_amounts | 支付关联表、商品汇总 | 全订单的金额核对表 |
| amount_difference_distribution | 金额核对表 | 按方向和大小分别统计的分布表 |
| summarize_payment_metrics | 支付工作表、支付汇总、金额核对表 | 指标字典，计数与金额为 Python 整数 |
| recheck_raw_order | 两张原始明细、金额核对表、样本订单 ID | 独立重算与订单结果的四项核对表 |

```python
payments_clean = clean_order_payments(raw_payments)
order_payment_summary = aggregate_order_payments(payments_clean)
orders_with_payments = join_orders_payments(raw_orders, order_payment_summary)
payment_controls = reconcile_payment_totals(
    payments_clean, order_payment_summary, orders_with_payments
)
items_clean = clean_order_items(raw_items)
order_item_summary = aggregate_order_items(items_clean)
orders_amount_check = reconcile_order_amounts(
    orders_with_payments, order_item_summary
)
metrics = summarize_payment_metrics(
    payments_clean, order_payment_summary, orders_amount_check
)
```

clean_order_payments 返回的是包含原字段和新增字段的整张新表；标记列、整数分列都属于这个返回表。它不会只返回几个标记或一个金额。

## 规则与类型

- 原始输入保留字符串；工作表为副本。payment_value 继续保留原始值，计算使用 payment_value_cents。
- payment_sequential 规范为正整数，payment_installments 规范为非负整数。转换后重新检查组合主键。
- 期数为 0 的原值保留并标记，其含义待核实；不得直接改为 1 或认定没有分期。
- 支付记录金额从字符串经 Decimal 精确换算为整数分；缺失、无法解析、非有限数、负数、精度不足一分时停止。
- 支付方式当前接受 credit_card、boleto、voucher、debit_card、not_defined。not_defined 单独标记；未覆盖标签或缺失值先停止核查。
- flag_payment_needs_review 是零金额、未定义支付方式、零期数三条记录级规则的并集。本数据为 11 行，不是删除清单。
- 缺少支付汇总时，金额、记录数使用可空整数 Int64，三个订单级支付特征使用可空 boolean，保持未知。
- flag_missing_payments 表示无支付记录；flag_amount_mismatch 表示可核对时是否有差额。后者在无法核对时为未知。
- amount_reconcile_status 明确区分金额完全一致、存在金额差额、无法核对。

## 控制总额与跨表差额

需要区别两种核对：

1. 同一来源在明细、汇总、关联后的控制总额：必须一致，否则停止处理。
2. 支付与商品两个来源间的金额差额：如实保留，输出核查清单。

支付记录数在三个层次均为 103,886，金额均为 1,600,887,212 分。商品侧也独立核对明细数、商品金额和运费。不同来源的业务金额不强制改成一致。

跨表差额定义为：

```text
payment_difference_cents
    = payment_amount_cents
    - goods_amount_cents
    - freight_amount_cents
```

只有三项金额都非空才核对；差额为 0 才完全一致。1 分、2～99 分、至少 100 分仅是观察分组，不是核对容差。全量净差额不能直接当作损失、利润或收益。
