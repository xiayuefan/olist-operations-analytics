# Olist 电商经营与履约优化分析

目标岗位：数据分析师实习生 / 数据运营实习生。技术主线：Python → MySQL → Power BI。

项目问题：经营变化来自哪里？哪些履约问题与差评相关？优先跟进哪些卖家？不同客户在相同观察窗口内的复购表现如何？

这是一个分阶段完成的个人学习项目。订单、商品明细、支付、评价、客户、商品与品类翻译、卖家、地理八个阶段已有可重复运行的清洗流程。MySQL 查询、专题分析和 Power BI 课件可按项目路线复现。

## 先从这里开始

1. 阅读 [项目路线](00_项目路线.md)，理解最终要交付什么。
2. 阅读 [第 1 课：认识数据](01_认识数据.md)，完成四个小练习。
3. 用 Jupyter 打开 `notebooks/01_认识数据.ipynb`，逐格执行并记录自己的理解。
4. 对照 `reports/01_原始数据盘点.md` 检查结果。这是盘点报告，不是清洗结果或业务结论。

当前学习进度为 Power BI 成交额增长瀑布图。可从 [第 53 课](45_PowerBI成交额增长瀑布图.md) 接着做，[第 54–62 课完整讲义](46_PowerBI剩余课程与项目交付.md) 提供八页报表的后续步骤、DAX 和对照值。最后用 [项目交付核对与答辩](47_项目交付核对与答辩.md) 记录实际报表结果和整理作品集。

前面的清洗课程使用 Pandas。Parquet 阶段使用项目 `.venv`，沿用 `myenv` 的 Python 3.8.20 和 Pandas 2.0.3，在项目虚拟环境中使用 PyArrow 17.0.0。核心依赖版本见 `requirements-parquet.txt`。

在项目根目录的 PowerShell 中生成并核对 Parquet。

```powershell
.\.venv\Scripts\python.exe .\src\10_export_parquet.py
```

九张表位于 `data/processed/mysql_input_v1/`，回读报告、关联检查和金额核对位于 `reports/mysql_input_v1/`。

在 PowerShell 中重新生成盘点报告：

```powershell
Set-Location 'D:\数据分析\olist-operations-analytics'
python .\src\01_profile_raw.py
```

打开 Notebook（如果尚未打开 Jupyter）：

```powershell
Set-Location 'D:\数据分析\olist-operations-analytics'
python -m notebook
```

## 目录

```text
D:\数据分析\
  archive\                         原始 CSV，保留原样
  olist-operations-analytics\
    README.md                      入口与进度
    docs\                         项目路线、课程、指标口径
    notebooks\                    自己逐步执行的学习与分析
    src\                          可重复运行的 Python
    reports\                      数据盘点与后续业务报告
```

订单脚本默认复现六规则 v1；使用 `python .\src\02_clean_orders.py --rules-version v2` 生成八规则 v2。两个版本分别保存在 `data/processed/orders_v1/`、`data/processed/orders_v2/` 与对应的 `reports/` 版本目录。建表、加载核对和经营专题查询见 `sql/`。Power BI 后续课程的分析表可运行 `.\.venv\Scripts\python.exe .\src\15_export_powerbi.py` 生成，报表在 Desktop 中完成后可保存到 `powerbi/`。

商品明细脚本：`python .\src\03_clean_items.py`。结果保存在 `data/processed/items_v1/` 与 `reports/items_v1/`，包含完整明细、订单级汇总、关联表、金额核对、核查清单和阶段报告。

支付脚本：`python .\src\04_clean_payments.py`。直接从三张原始 CSV 运行，复用商品阶段函数；结果保存在 `data/processed/payments_v1/` 与 `reports/payments_v1/`，包含支付明细、订单汇总、覆盖检查、金额差额与无法核对清单、原始样本复核和阶段报告。完全一致、存在差额、无法核对分别计数；不擅自修正跨表差异。

评价脚本：`python .\src\05_clean_reviews.py`。从原始评价和订单表独立运行；结果保存在 `data/processed/reviews_v1/` 与 `reports/reviews_v1/`。明细全部保留，按规则选每单最新评价，再聚合和关联；输出两种规则对照、无评价清单、控制总额及阶段报告。

客户脚本：`python .\src\06_clean_customers.py`。保留全部客户记录，规范地区字段并对照 IBGE 州代码，按 customer_id 关联订单，再按州城市组合统计。结果保存在 `data/processed/customers_v1/` 和 `reports/customers_v1/`。客户标识观察计数尚非最终复购指标。

商品与品类翻译脚本：`python .\src\07_clean_products.py`。保留完整商品，区分来源品类缺失与未翻译，分别计算重量和体积资格，再以商品 ID 多对一关联销售明细；数量和整数分金额不变。结果保存在 `data/processed/products_v1/` 和 `reports/products_v1/`，使用全部明细、全部订单状态。商品表主键为 product_id，关联后销售明细仍以 order_id + order_item_id 为组合主键。

用 `python .\src\08_clean_sellers.py` 运行卖家阶段。数据表位于 `data/processed/sellers_v1/`，检查报告位于 `reports/sellers_v1/`。卖家订单数合计按订单＋卖家关系数核对，全局订单数按商品明细中的不同订单 ID 核对。

用 `python .\src\09_clean_geolocation.py` 运行地理阶段。代表坐标按邮编前缀与州分组，取候选记录的经纬度中位数。数据表位于 `data/processed/geolocation_v1/`，覆盖报告和异常清单位于 `reports/geolocation_v1/`。

## 完成标准

每一阶段都要留下代码或操作记录、结果、检查证据和自己的解释。完成项目后再根据真实结果撰写简历，不把目标工作量、建议收益或模拟实验写成已经完成的实绩。

数据目录默认为项目的同级 `archive/`。换电脑时可使用：

```powershell
python .\src\01_profile_raw.py --data-dir '实际的原始CSV文件夹'
```

公开作品时说明数据来自 [Olist 公开数据集](https://www.kaggle.com/datasets/olistbr/brazilian-ecommerce)，先核对原数据许可与署名要求；代码、文档、图表与原始数据分开管理。
