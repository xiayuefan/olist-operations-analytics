## 为什么现在学函数

目前的 Notebook 已逐段说明业务判断。把相关代码放到函数中，可以从原始输入一次性重新生成工作表，避免漏运行某个单元格或运行顺序变化影响结果。

这次重点理解三件事：输入、工作副本、返回值。先看一个最小例子：

```python
def add_review_flag(df, flag_cols):
    result = df.copy()
    result['flag_needs_review'] = result[flag_cols].any(axis=1)
    return result

example_result = add_review_flag(orders_clean, flag_cols)
```

- `def` 定义一个函数；定义时不会处理数据。
- `df` 和 `flag_cols` 是参数，调用时传入真实数据和列名。
- `copy()` 创建副本，保护调用者传入的表。
- `return` 把计算后的表交回调用者；调用者需要用变量接住它。

完整课堂整理位于 `src/orders_cleaning.py`，其中 `clean_orders(raw_orders)` 返回整理后的新表，`summarize_metrics(cleaned)` 返回课堂指标。它们复用课堂已学规则。

## 当前六条核查规则

| 标记 | 触发条件 | 第一版处理 |
| --- | --- | --- |
| flag_delivered_missing_date | 已交付，实际送达时间缺失 | 保留记录；依赖该时间的指标无法计算 |
| flag_delivered_missing_approval | 已交付，审批时间缺失 | 保留记录；涉及审批的耗时无法计算 |
| flag_delivered_missing_carrier | 已交付，交物流时间缺失 | 保留记录；运输耗时无法计算 |
| flag_carrier_before_purchase | 两时间存在且交物流早于下单 | 标记；不纳入当前有效运输样本 |
| flag_delivery_before_carrier | 两时间存在且送达早于交物流 | 标记；不纳入当前有效运输样本 |
| flag_canceled_has_delivery_date | 取消状态且实际送达时间存在 | 核查；保留取消状态，已交付主口径不纳入 |

极长但顺序合理的运输耗时暂时保留；P99 不是自动删除阈值。

## 两个指标的范围

运输耗时为送达时间减交物流时间，以秒换算成天。当前有效样本要求已交付，下单、交物流、送达时间存在，且无上述两类倒置。

延迟天数按实际送达日期减预计送达日期计算。当前有效样本要求已交付、相关日期存在、实际送达不早于下单、预计送达日期不早于下单日期。大于零为延迟，零为预计当天送达，负数为提前。

两个指标各有自己的样本条件；`flag_needs_review` 不作为统一的指标删除条件。后续需比较保留和排除其他时间冲突记录时的延迟率，检查结论是否敏感。

## 脚本与保存结果

在项目目录的终端运行：

```powershell
python .\src\02_clean_orders.py
```

它会从原始文件重建数据并保存：

- `data/processed/orders_v1/orders_clean_v1.csv`：含六类标记、有效样本标记和指标的全部订单。
- `reports/orders_v1/orders_review_v1.csv`：218 笔待核查订单及触发规则。
- `reports/orders_v1/quality_summary_v1.csv`：规则计数。
- `reports/orders_v1/metrics_v1.json`：未四舍五入的指标，延迟率以 0–1 小数保存。
- `reports/orders_v1/run_info_v1.json`：来源、环境与规则版本说明。

这一阶段先保存 CSV 便于检查。CSV 不保存 Pandas 的日期类型，重新读取时需要转换；Parquet 将在环境配置步骤补充，不直接升级现有环境。

脚本遇到缺少必需列、主键异常、未知状态或非空日期解析失败会停止并提示，避免未经核查的问题继续影响指标。当前数据已验证满足这些前提。
