## 字段规范与标记

保留原始客户记录，工作副本仅去地区字段首尾空白、统一城市小写和州大写。邮编保持字符串，不擅自补零、截断或猜测缺失地区。

| 检查项 | 原始缺失数 | 非空但只有空白字符数 | 规范后变化记录数 |
| --- | --- | --- | --- |
| customer_zip_code_prefix | 0 | 0 | 0 |
| customer_city | 0 | 0 | 0 |
| customer_state | 0 | 0 | 0 |

| 检查项 | 记录数 |
| --- | --- |
| flag_zip_format_invalid | 0 |
| flag_state_format_invalid | 0 |
| flag_state_unknown | 0 |
| flag_city_missing | 0 |

州缩写除两位大写字母格式外，还对照 [IBGE 官方州/联邦区代码](https://servicodados.ibge.gov.br/api/v1/localidades/estados?orderBy=nome) 的项目参考快照。参考代码 27 个，校验时无需联网。邮编格式通过不等于已完成邮编、城市、州的地理一致性校验。

同名城市分州区分，城市拼写差异和邮编地理覆盖仍需后续地理表核查；本阶段没有模糊合并城市。

## 同一客户标识的地区差异

有 250 个客户标识对应多个邮编值，122 个对应多个州+城市组合，39 个对应多个州标签。这些是字段观察，不能直接推断迁居、身份变化或具体原因。

保留每个 customer_id 的地区信息，让订单关联到各自的客户记录。不能任意按 customer_unique_id 取一条地址并覆盖所有历史订单。

## 输出与后续

数据目录：D:\数据分析\olist-operations-analytics\data\processed\customers_v1。

输出客户工作表、订单客户关联、客户标识观察表、地区订单统计、字段变化、地区核查及多地区客户标识清单。metrics_v1.json 和 run_info_v1.json 记录精确计数、来源哈希、环境和参考版本。

下一阶段继续商品、卖家、地理和品类翻译表。复购定义、有效订单状态、正式时间窗口和地区地理一致性后续明确。当前没有计算最终复购率或将订单数当作客户人数。

CSV 重新读取时显式保留 ID 和邮编为字符串；日期、布尔类型需按元数据恢复。Parquet、MySQL 和 Power BI 在相应阶段接入。
